# RecruitOS 演示环境数据准备说明

本文档用于说明 `backend/src/seed.ts` 在本项目中的作用、初始化内容与使用方式，便于研发、测试、产品演示快速准备统一环境。

---

## 1. 目的与作用

`seed.ts` 是演示环境初始化脚本，目标是：

- 快速准备一套可直接登录、可直接走流程的演示数据；
- 保证多人协作时数据基线一致，便于复现问题；
- 覆盖一期主流程 + 二期能力 + HR Agent 联调所需关键场景。

---

## 2. 数据准备范围（脚本做了什么）

## 2.1 清理历史数据

脚本启动后会按依赖顺序执行大量 `deleteMany()`，清理旧数据（包括一期与二期表），避免外键冲突导致初始化失败。

## 2.2 组织与账号

创建组织树：

- `示例科技有限公司`（根组织）
- `研发中心`
- `人力资源部`
- `产品部`

创建 8 个演示账号（统一密码 `123456`，bcrypt 哈希存储）：

- `admin`（系统管理员）
- `lead`（招聘负责人）
- `hr`（招聘HR）
- `dept`（用人部门负责人）
- `interviewer`（面试官）
- `approver`（Offer审批人）
- `ops`（人事运营）
- `viewer`（数据查看）

## 2.3 基础字典与模板

初始化常用字典（示例）：

- 招聘原因、候选来源、淘汰原因、Offer 拒绝原因、放弃原因
- 学历、城市、职级

初始化模板：

- 面试评价模板（六维）
- 面试通知模板
- Offer 模板
- 入职材料清单模板

## 2.4 一期主流程样例数据

创建 1 条招聘需求 + 1 个职位（高级前端工程师），并配置职责、要求、发布文案等字段。

创建 3 位候选人，覆盖关键流程分支：

1. 候选 A：HR 筛选淘汰（`REJECTED`）
2. 候选 B：面试后淘汰并入人才库（`REJECTED + rejectToPool`）
3. 候选 C：推进到面试阶段（用于继续演示 Offer/入职）

同时写入配套数据：

- `ProcessEvent` 流程事件时间轴
- `Interview` / `InterviewEvaluation` 面试与评价
- `Todo` 待办
- `Activity` 最近动态

## 2.5 二期能力样例数据

初始化并绑定：

- 评价模型（`EvalModel`）
- 流程模板（标准流程 + 快速通道）
- 岗位标准（`JobStandard`）并回写职位
- 渠道与模拟发布记录
- SLA 规则与告警订阅
- Agent 语义字典（高风险动作、业务语义等）

## 2.6 门户与联调数据

为候选 C 创建 `SecureLink`（门户 token），并写入：

- 面试可选时段（`slotOptions`）
- 面试资料包内容（`packContent`）

脚本执行结束会输出：

- 演示账号清单
- 门户演示链接：`/portal/<token>`
- 流程模板名称

---

## 3. 如何执行

在仓库根目录执行：

```bash
# 仅重灌演示数据（不重置库结构）
npm --prefix backend run db:seed

# 重置数据库后再灌入演示数据（推荐演示前使用）
npm --prefix backend run db:reset
```

---

## 4. 演示验收建议路径

建议使用 `hr` 账号起流程，按角色切换完成关键节点：

1. 查看需求与职位（在招状态）
2. 演示候选 A 的淘汰路径
3. 演示候选 B 的面试后淘汰并入库
4. 推进候选 C 的面试、评价、Offer、入职衔接
5. 进入 `HR Agent` 页面做 JD 生成、简历解析、分析问答联调

---

## 5. 注意事项

- 本脚本会清空大量业务数据，请勿在生产库执行。
- 演示密码为固定值 `123456`，仅用于本地/测试环境。
- 若需保留既有数据，请不要执行 `db:reset`，仅在隔离环境演示。
