## 术语表

| 术语               | 说明                                                      |
| ---------------- | ------------------------------------------------------- |
| Agent            | 基于大语言模型的智能体，能理解自然语言意图并调用工具完成复杂任务                        |
| OCR              | Optical Character Recognition，光学字符识别，将图片/扫描件中的文字转为可编辑文本 |
| RAG              | Retrieval-Augmented Generation，检索增强生成，先检索知识库再由LLM生成答案   |
| Embedding        | 将文本映射为高维向量，用于语义相似度计算                                    |
| Hybrid Search    | 混合检索，结合BM25关键词检索与向量语义检索                                 |
| Rerank           | 对检索结果进行二次排序，提升相关性                                       |
| Knowledge Object | 知识对象，系统对合同、条款、订单等数据的知识化抽象                               |
| EARS             | Easy Approach to Requirements Syntax，需求描述语法规范           |
| 企业商业记忆           | Enterprise Business Memory，企业历史交易经验的沉淀与复用体系             |
| 履约               | 合同签订后双方按约定执行义务的过程                                       |
| 履约时间线            | AI从合同中提取的关键时间节点序列，含付款、交付、验收、期限等节点                       |
| 履约节点             | 履约时间线中的单个时间节点，含类型、日期、责任人、状态                             |
| 履约预警             | 在履约节点到期前向责任人发送的提醒通知                                     |
| 客户画像             | 基于合同、订单、交易数据自动生成的客户合作全貌                                 |

# 1 文档说明

## 1.1 文档目的

本文档用于明确法务Agent α版本的产品定位、建设目标、功能设计及技术方案，为产品研发、UI设计、技术架构、测试验收及后续版本迭代提供统一依据。

本文档适用于：产品经理、技术架构师、开发工程师、测试工程师、UI/UX设计师、项目管理人员。

---

## 1.2 产品背景

随着企业数字化建设不断推进，大量合同、订单、协议等商业资料已实现电子化存储，但仍普遍存在以下问题：

- 合同数量庞大，查找效率低；
- 历史合同未形成企业知识资产，优秀经验无法复用；
- 合同信息分散在多个系统，业务数据关联性弱；
- 企业商业模式、风险经验依赖个人经验，缺乏沉淀机制；
- AI能力缺乏企业私有数据支撑，无法真正服务业务；
- 合同履约跟踪依赖人工记忆，重要节点容易遗漏。

因此，需要建设一套以合同为核心、以AI为驱动的企业知识资产平台，实现企业商业经验的持续沉淀与复用，并通过智能履约管理降低企业履约风险。

---

## 1.3 产品范围（α版本）

α版本重点建设企业知识底座，实现企业合同及交易数据的统一接入、智能解析、知识抽取、智能检索、履约管理和客户供应商归集。

**本版本包括：**

- 工作台（AI智能对话框 + 四个AI模块入口）
- 合同AI：合同导入与解析（整合上传+OCR）、合同智能标签、企业合同搜索、合同摘要
- 履约AI：供应商中心、客户中心、履约助手AI
- 知识资产AI：企业知识问答
- 商业模式AI（预留入口）
- 系统管理（基础）

**暂不包含：**

- 合同起草审核
- 商业模式分析（仅预留入口）
- 风险预测

上述能力将在后续版本逐步实现。

# 2 产品概述

## 2.1 产品定位

法务Agent并非传统意义上的合同管理软件或法律数据库，而是**以合同为载体、以AI Agent为交互入口、以企业知识资产为核心的智能管理平台**。

产品通过持续沉淀企业合同、订单及交易过程中的商业经验、法律经验和管理经验，构建企业专属知识资产体系，实现知识的持续积累、共享和复用。

产品最终目标不是"管理合同"，而是帮助企业建立**企业商业记忆（Enterprise Business Memory）**，让历史交易经验持续服务未来业务。

---

## 2.2 产品目标

α版本目标：建立企业知识底座，实现：

- 合同统一管理
- 企业知识沉淀
- AI智能检索
- 企业经验复用
- 智能履约管理

形成企业合同知识库、交易知识库及履约管理体系。

---

## 2.3 产品原则

### （1）知识优先

所有业务数据均应沉淀为可检索、可复用的知识对象。

### （2）AI优先

所有核心业务均应支持AI交互。优先自然语言，而非复杂菜单。

### （3）数据可追溯

所有AI回答必须引用原始合同、条款或订单（提供引用链接），不允许生成无法验证的信息。

### （4）持续积累

所有合同、订单、知识均应成为企业长期资产。

---

## 2.4 产品价值

### 对个人

- 提高合同查询效率
- 提高合同理解效率
- 减少重复劳动
- 避免履约遗漏

### 对组织

- 建立统一知识资产
- 沉淀企业交易经验
- 实现知识共享
- 降低履约违约风险

### 对经营

- 提升企业数据利用率
- 支撑经营分析
- 为商业决策提供依据

# 3 用户分析

## 3.1 用户角色

| 角色    | 核心需求                     | 使用频率   |
| ----- | ------------------------ | ------ |
| 法务人员  | 合同管理、历史案例查询、条款参考、履约跟踪    | 高频（每日） |
| 业务人员  | 查询合作案例、了解交易历史、查看客户信息     | 中频（每周） |
| 销售人员  | 客户管理、订单跟踪、销售额查看、客户交易历史   | 高频（每日） |
| 采购人员  | 查看供应商历史合作情况、跟踪履约节点       | 中频（每周） |
| 财务人员  | 付款节点跟踪、合同金额统计、回款监控       | 中频（每周） |
| 管理人员  | 查看企业知识资产、经营数据及履约概况       | 低频（每月） |
| 系统管理员 | 用户管理、权限配置、系统配置           | 按需     |

---

## 3.2 用户痛点

### 法务人员

- 历史合同难以检索；
- 相似案例难以复用；
- 大量重复查询工作；
- 履约节点容易遗漏。

### 业务人员

- 不清楚历史合作模式；
- 找不到历史合同；
- 无法快速了解合同内容；
- 不了解客户历史交易全貌。

### 采购人员

- 不清楚供应商历史合作全貌；
- 缺乏供应商/客户交易数据汇总；
- 履约到期缺少提醒。

### 销售人员

- 不了解客户历史交易全貌；
- 无法掌握客户销售额/销售量趋势；
- 客户关联关系不清晰，集团客户归集困难。

### 财务人员

- 付款节点跟踪依赖人工；
- 无法快速统计合同金额和回款情况。

### 管理人员

- 无法掌握企业知识资产；
- 合同数据无法支撑经营决策；
- 企业经验依赖个人；
- 无法掌握整体履约风险。

---

## 3.3 用户价值

| 角色   | 价值                                               |
| ------ | -------------------------------------------------- |
| 法务   | 定位历史合同，总结商业模式，赋能企业交易良性运转   |
| 业务   | 快速找到案例、快速学习经验、掌握客户全貌           |

| 管理层 | 掌握企业知识资产、交易情况和履约风险               |

## 4.4 知识架构

所有数据最终统一抽象为**知识对象（Knowledge Object）**。

包括：合同（Contract）、条款（Clause）、订单（Order）、供应商（Supplier）、客户（Customer）、项目（Project）、风险（Risk）、标签（Tag）、履约节点（PerformanceNode）。

所有知识对象均支持：搜索、AI问答、标签、Embedding、引用。

## 5.3 AI问答流程

```
用户提问
 ↓
意图识别
 ↓
Query Rewrite
 ↓
Hybrid Search（BM25 + Embedding）
 ↓
Rerank
 ↓
LLM生成
 ↓
引用合同/条款/订单

```

---

## 5.4 履约管理流程

```
合同解析完成
 ↓
AI提取履约时间线 + 推荐责任人
 ↓
人工确认时间点和责任人（可多责任人）
 ↓
履约计划生效
 ↓
定时监控节点状态
 ↓
到期前预警通知全部责任人
 ↓
责任人确认完成 / 申请调整（上传证据→审批）
 ↓
履约分析归集
```

```

```
