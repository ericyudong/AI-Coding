## 6.1 工作台（Workbench）

### 6.1.1 功能概述

工作台是法务Agent面向企业用户的统一智能交互入口。工作台以**AI智能对话框为核心交互方式**，以**四个AI模块（合同AI、履约AI、商业模式AI、知识资产AI）为能力组织方式**。

```
┌──────────────────────────────────────────────┐
│              法务Agent 工作台                  │
├──────────────────────────────────────────────┤
│            AI智能对话框                        │
│   "请输入您想了解的问题……"                       │
├──────────────────────────────────────────────┤
│合同AI  │  履约AI  │ 商业模式AI  │ 知识资产AI  
└──────────────────────────────────────────────┘
```

**四个AI模块定位：**

1. **知识资产AI** — 企业知识问答、知识库浏览。
2. **合同AI** — 合同导入与解析、搜索、详情/列表、摘要。
3. **履约AI** — 供应商中心、客户中心、履约助手AI。
4. **商业模式AI（预留）** — 商业经验沉淀与分析。

---

### 6.1.2 产品目标

**（1）打造企业知识交互入口** — "查文件" → "问企业知识"

**（2）提升企业知识利用效率** — 合同 → 数据 → 知识 → 智能决策

**（3）连接交易全生命周期** — 签约前（商业模式参考）→ 签约中（合同AI）→ 签约后（履约AI）→ 复盘（知识资产AI）

---

| 销售人员  | 客户管理、订单跟踪、销售额查看、客户交易历史 |
| 采购人员  | 供应商管理、订单跟踪、履约预警        |
| 财务人员  | 付款节点跟踪、合同金额统计、回款监控     |
| 项目负责人 | 合同执行跟踪、交付管理            |
| 管理人员  | 知识资产总览、履约概况、经营洞察       |

### 6.1.5 功能模块设计

#### 一、AI智能对话框

**定位：** 工作台第一入口，通过自然语言访问企业知识资产。

**能力：** 企业知识问答、智能分析（合同对比/条款分析/风险识别）。

| 元素     | 说明          |
| ------ | ----------- |
| 输入框    | 用户问题输入      |
| 推荐问题   | 根据用户角色动态生成  |
| 历史记录   | 可收起的侧边栏历史对话 |
| 引用来源   | 展示来源并支持一键跳转 |
| 深度分析按钮 | 调用Agent分析能力 |

| 编号       | 类型           | 需求描述                                   |
| -------- | ------------ | -------------------------------------- |
| WB-AI-01 | Ubiquitous   | 系统应始终在工作台顶部展示AI对话框及推荐问题。               |
| WB-AI-02 | Event-driven | 当用户提交问题时，系统应在5秒内返回首条响应。                |
| WB-AI-03 | Unwanted     | 如果知识库不存在相关信息，系统应提示"未检索到相关企业数据"，不得编造答案。 |
| WB-AI-04 | Event-driven | 当引用来源被点击时，系统应跳转至对应原文。                  |

## 6.2 合同AI

### 6.2.1 合同导入与解析（Contract Import & OCR Engine）

#### 功能概述

合同导入与解析负责企业合同资产的统一接入与智能解析，将上传、OCR识别、版面恢复、字段提取、条款拆分整合为同一流程，是整个知识库建设的数据入口。

**核心设计原则：用户只需一次性上传文件，后台异步完成全部解析工作。用户无需等待、无需重复上传，解析结果通过解析日志体现。**实现最简便的上传模式，即拖拽单个文件或整个文件夹（不区分文件格式）做到一次性上传，上传后

---

#### 页面布局

```
合同导入与解析
──────────────────────────────────────
[ 拖拽文件到此区域 ]  或  [ 选择文件 ]
──────────────────────────────────────
支持格式：PDF / Word / JPG / PNG
单文件 ≤ 100MB，支持批量上传（≥50个）
──────────────────────────────────────
解析日志
文件名              状态        进度     操作
采购合同.pdf        解析完成    100%    [查看详情]
软件合同.doc        解析中      60%     —
服务协议.pdf        解析失败     —      [查看原因] [重新解析]
租赁合同.jpg        排队中       —      —
──────────────────────────────────────
[全部上传成功，后台正在解析…] [共4个文件，成功3，处理中1]
```

---

#### 核心机制

**后台异步解析流程：**

```
用户上传文件 → 文件校验 → 加入异步队列 → OCR识别 → 版面恢复 → 字段抽取 → 条款拆分 → AI语义理解 → 更新解析日志
```

| 规则     | 说明                |
| ------ | ----------------- |
| 异步执行   | 上传后立即返回，解析在后台独立进行 |
| 解析日志   | 实时展示每个文件的解析状态     |
| 失败自动重试 | 解析失败后自动重试1次       |
| 无需重新上传 | 失败文件从后台直接触发重试     |

**OCR解析内容：** 版面恢复（标题/正文/表格/页眉/页脚/签章）、字段抽取（合同名称/编号/金额/日期/主体/联系方式）、条款识别（标的/付款/验收/保密/违约/知识产权/不可抗力/争议解决）、AI语义理解。

---

#### 异常处理

| 场景       | 系统处理               |
| -------- | ------------------ |
| 文件损坏     | 自动重试1次，仍失败标记"解析失败" |
| 文件格式错误   | 上传前拦截              |
| 文件>100MB | 上传前提示              |
| OCR识别率低  | 标记"需人工复核"          |
| AI解析失败   | 自动重试1次，失败标记"解析异常"  |
| 网络中断     | 已上传文件保留，恢复后继续      |
| 重复文件     | 提示是否覆盖             |

---

#### EARS需求

| 编号    | 类型           | 需求描述                             |
| ----- | ------------ | -------------------------------- |
| CI-01 | Ubiquitous   | 系统应始终支持PDF、DOC、DOCX、JPG、PNG格式上传。 |
| CI-02 | Unwanted     | 如果格式不支持，上传前即提示。                  |
| CI-03 | Unwanted     | 如果文件损坏，标记失败并记录原因，用户无需重新上传。       |
| CI-04 | Event-driven | 上传完成后立即返回提示，后台自动加入解析队列。          |
| CI-05 | Event-driven | 解析状态变化时实时更新解析日志。                 |
| CI-06 | Unwanted     | 解析失败自动重试1次；仍失败则标记，支持后台"重新解析"。    |
| CI-07 | Ubiquitous   | 系统应始终在后台异步执行OCR解析，不阻塞用户操作。       |
| CI-08 | Event-driven | OCR完成时自动进行字段提取和条款拆分。             |
| CI-09 | Event-driven | 解析全部完成时自动触发标签生成和摘要生成。            |
| CI-10 | Unwanted     | OCR准确率低于阈值，标记"需人工复核"。            |

### 6.2.2 合同详情（Contract Detail）

#### 功能概述

合同详情是合同AI的核心页面，整合**合同列表、合同详细视图、智能标签和合同摘要**为一体。用户通过合同列表快速定位合同，点击进入详情后可查看完整合同信息、智能标签、摘要和履约时间线。

智能标签不作为独立页面存在，而是作为合同详情页中的一部分展示和编辑。

#### 智能标签（合同详情页内）

合同详情页右侧或"智能标签"区域展示AI自动生成的标签。标签支持：

- AI自动生成（解析完成后触发）
- 人工新增/删除/修改
- 人工修改优先级高于AI
- 变更历史可追溯
- 企业可自定义标签体系

**标签体系：** 一级（采购合同/销售合同/通用合同）→ 二级（软件采购/硬件采购/云服务采购/原材料采购/服务采购；软件销售/硬件销售/服务销售/解决方案销售/产品分销；保密协议/合作协议）→ 三级及其他智能标签（不限类型，AI灵活生成：SaaS/年度框架/按里程碑付款/源代码交付/对赌条款等）。

### 6.2.5 合同版本管理（Contract Version Management）

#### 功能概述

同一合同在履行过程中可能产生多个版本（如补充协议、变更协议、续签等）。合同版本管理功能确保版本间关联的同时，**不重复建立合同台账**——即同一合同的不同版本共享一份合同档案，仅以版本号区分内容变化。

---

#### 核心机制

**版本识别规则：**

| 识别方式 | 说明 |
| --- | --- |
| 同一合同编号 | 系统自动识别合同编号相同的上传文件为同合同的不同版本 |
| 人工关联 | 若合同编号不同但实为同一合同，支持人工指定关联 |
| Hash检测 | 内容完全相同的文件自动识别为重复，不创建新版本 |

**版本管理规则：**

| 规则 | 说明 |
| --- | --- |
| 版本号递增 | 首个上传为V1.0，后续版本依次编号V1.1、V1.2… |
| 共享台账 | 所有版本共享同一份合同档案（名称/编号/主体/标签），不重复创建 |
| 版本对比 | 支持选择任意两个版本进行差异对比（AI高亮变更内容） |
| 流水记录 | 自动记录每次变更：新版本上传时间、上传人、变更概述（AI提取） |
| 履约继承 | 新版本上传后，履约计划默认继承上一版本，用户确认后更新 |

**页面设计：**

```
合同详情 > 版本管理
────────────────────────────────
《采购合同》C2026001
────────────────────────────────
版本历史
┌────────────────────────────────────────┐
│ V1.2  2026-06-15  张法务 上传           │
│       变更：增加补充协议，延长交付期限     │
│       [查看] [对比V1.1]                 │
├────────────────────────────────────────┤
│ V1.1  2026-05-10  张法务 上传           │
│       变更：调整付款方式为分阶段付款      │
│       [查看] [对比V1.0]                 │
├────────────────────────────────────────┤
│ V1.0  2026-03-15  张法务 上传           │
│       初始版本                          │
│       [查看]                            │
└────────────────────────────────────────┘
[上传新版本]
```

---

#### EARS需求

| 编号 | 类型 | 需求描述 |
| --- | --- | --- |
| CV-01 | Ubiquitous | 系统应始终将同一合同编号的文件识别为同一合同的版本，不重复建立合同台账。 |
| CV-02 | Event-driven | 当用户上传与已有合同编号相同的文件时，系统应自动识别为版本更新并提示用户确认。 |
| CV-03 | Event-driven | 当用户选择两个版本进行对比时，系统应AI标注变更内容差异。 |

### 6.3.3 履约助手AI（Performance Compliance Assistant）

#### 功能概述

履约助手AI是履约AI的核心子模块。系统基于已解析的合同详情，由AI自动识别关键时间节点，生成履约时间线。**AI提取后需人工确认时间点和责任人**，确认后履约计划生效。履约过程中可调整时间点，**调整需提供相应证据并经过审批**。

系统在节点到期前自动预警通知责任人，支持对单个合同、各类合同及企业整体的履约情况进行AI分析。

**履约节点支持多个责任人。**

---

#### 功能目标

- AI自动提取履约时间线 → **人工确认后生效**
- 指定/调整责任人（支持多人）
- 节点到期前智能预警
- 履约时间线可视化（时间轴）
- 按责任人权限隔离履约数据
- 单合同/分类/企业履约分析

---

#### 用户场景

**场景一：AI提取 → 人工确认**

AI解析合同后自动识别时间节点和推荐责任人，生成待确认履约计划：

| 节点     | 日期         | 期间     | 责任人（待分配） | 类型   | 状态  |
| ------ | ---------- | ------ | ------------ | ---- | --- |
| 合同生效   | 2026-03-01 | —      | —            | 基础节点 | 已确认 |
| 首付款30% | 2026-03-15 | 14天    | 张三（采购）       | 付款节点 | 待确认 |
| 软件交付   | 2026-04-30 | 46天    | 李四、王五（供应商对接） | 交付节点 | 待确认 |
| 验收截止   | 2026-06-30 | 15个工作日 | 赵六（业务）       | 验收节点 | 待确认 |
| 尾款70%  | 2026-07-15 | 15天    | 张三（采购）       | 付款节点 | 待确认 |

用户逐项确认或修改后，履约计划正式生效。未确认的节点不进入预警监控。

**调整流程：** 履约过程中如需调整时间点或变更责任人，需：

1. 提交调整申请，说明调整原因
2. **上传相应证据**（如对方延迟交付的邮件截图、变更协议、不可抗力证明等）
3. 提交审批（审批人为部门负责人或法务负责人）
4. 审批通过后更新履约计划，记录变更历史

**场景二：按责任人查看待履约事项**

系统根据责任人身份展示其负责的履约节点：

- **普通责任人：** 仅可查看自己被指定为责任人的合同履约节点，不显示他人负责的节点和其他部门的合同
- **法务人员、管理人员、财务人员：** 可查阅全部合同的履约数据
- 同一节点有多个责任人时，每位责任人均可在各自待办中看到该节点

```

────────────────────

  到期：2026-03-15  剩余：5天
  关联责任人：张三

⏳ 《软件服务合同》    交付节点    李四  负责
  到期：2026-04-30  剩余：30天

⚠ 《采购合同-001》    验收截止    王五、李四  共同负责
  到期：2026-03-20  剩余：2天
```

**场景三：到期前预警通知**

节点到期前N天（默认7天）向节点所有责任人发送通知。

**场景四：单合同履约分析**

AI生成履约情况报告：进度、健康度、各节点状态、延迟原因、风险提示。

| 点击节点  | 进入节点详情页，可操作（标记完成/延期/添加备注）  |
| 缩放    | 支持按月份/季度/年度切换时间粒度          |
| 筛选    | 可按节点类型筛选（全部/付款/交付/验收/期限）   |
| 展开/折叠 | 长期合同（>2年）支持折叠中间闲置期         |

**场景六：分类归集/企业总览**

按合同类型归集履约分析。管理层通过总览看板查看全企业履约概况。

---

#### 核心功能

##### （1）AI时间线提取 + 人工确认

解析完成后AI自动提取节点 → 展示待确认列表 → 用户逐项确认/修改/补充 → 确认后履约计划生效。

##### （2）手动分配责任人

责任人由用户**手动分配**，系统不自动推荐。

- AI提取时间节点后，责任人列默认为空（"待分配"）
- 用户为每个节点手动指定一个或多个责任人
- 支持按部门筛选可选责任人列表
- 已分配责任人的节点方可进入预警监控

##### （3）多人责任人

每个履约节点支持指定**多个责任人**：

- 多个责任人均会在待办中看到该节点
- 任一责任人标记完成后，节点状态更新
- 预警通知发送给所有责任人
- 支持主责任人 + 协助责任人的角色区分

##### （3）履约调整与审批

履约过程中可申请调整时间点或责任人：

1. 提交调整申请（说明原因）
2. **上传证据**（必填，支持图片/PDF/截图）
3. 提交审批（审批人：部门负责人或法务负责人）
4. 审批通过 → 更新计划 + 记录变更历史
5. 审批拒绝 → 保持原计划 + 记录拒绝原因

##### （4）到期预警通知

| 配置项    | 默认值   | 可配置        |
| ------ | ----- | ---------- |
| 提前预警天数 | 7天    | 3/7/15/30天 |
| 二次提醒   | 到期前1天 | 是          |
| 逾期提醒   | 到期后每天 | 可关闭        |
| 通知方式   | 站内+邮件 | 可扩展企微/钉钉   |

##### （5）履约状态管理

```
待履约 → 进行中 → 已完成
                → 已延迟
                → 已违约
```

逾期无宽限期，超期立即自动标记"已违约"。支持操作：标记已完成、申请调整（审批）、标记违约、添加备注。

##### （6）履约分析看板

单合同分析、分类归集分析、企业总览三层分析体系。

**履约数据权限：**

| 角色    | 可见范围             |
| ----- | ---------------- |
| 普通责任人 | 仅可见自己负责的合同履约节点   |
| 法务人员  | 全部合同履约数据         |
| 财务人员  | 全部合同履约数据（侧重付款节点） |
| 管理人员  | 全部合同履约数据         |
| 部门负责人 | 本部门全部合同履约数据      |

非负责部门的用户不能查阅该部门的合同履约信息。

## 13.1 α版本功能模块总结

**工作台：** AI对话框 + 四模块入口（知识资产AI/合同AI/履约AI/商业模式AI预留）

**系统管理：** 7角色权限、部门级权限切分、标签管理、系统配置、审计
