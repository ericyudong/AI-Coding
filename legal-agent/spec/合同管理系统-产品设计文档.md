# 合同管理系统 - 产品需求与设计方案

## 一、产品概述

### 1.1 产品定位
基于AI原生的智能合同管理系统，以AI能力为核心驱动，重塑合同全生命周期管理流程。从合同导入、解析、管理、检索到问答分析，全面实现智能化、自动化。

### 1.2 产品愿景
"让每一份合同都被AI理解，让每一次查看都获得洞察。"

### 1.3 目标用户
- **法务人员**：合同审核、条款比对、风险识别
- **业务人员**：合同查阅、关键信息提取
- **管理人员**：合同台账总览、数据分析
- **行政/档案人员**：合同归档、录入管理

### 功能二：合同导入与OCR解析 (Contract Import & OCR Parsing)

#### 2.2.1 功能描述
支持多种格式合同文件的导入，通过AI OCR技术自动识别扫描件/图片中的文字内容，并结构化提取关键字段。

#### 2.2.2 支持的导入方式
| 方式 | 说明 | 格式 |
|------|------|------|
| 文件上传 | 拖拽或选择文件 | PDF / Word / Excel / 图片 |
| 批量导入 | 多文件/文件夹导入 | 同上 |
| 邮件导入 | 转发邮件自动解析 | 解析邮件附件 |
| 扫描仪集成 | 连接扫描设备 | 自动识别 |

#### 2.2.3 OCR处理流程
```
文件上传 → 格式预处理 → OCR文字识别 
    ↓                      ↓
  结构化提取 ←──── AI模型解析 ←── 图像增强
    ↓
  字段确认界面 → 用户校对 → 入库
```

#### 2.2.4 AI提取字段清单
- 合同名称、编号
- 签约日期、生效日期、到期日期
- 签约双方名称
- 合同总金额（数字+币种）
- 付款条款、付款节点
- 违约责任条款
- 争议解决方式
- 保密义务条款
- 合同续签条款

#### 2.2.5 交互设计
1. **上传即解析**：上传后后台自动启动OCR+AI解析，解析过程显示进度
2. **人机协同校对**：AI提取结果以"标注"形式展示在原始文档预览上，用户可点选确认/修改
3. **置信度标记**：AI对每个提取字段标注置信度（高/中/低），低置信度字段高亮提示人工确认
4. **学习反馈**：用户对OCR结果的修正将被记录，用于后续模型微调

### 功能三：合同智能标签 (Smart Contract Tagging)

#### 2.3.1 功能描述
利用AI自动为合同生成多维度的标签体系，支持标签检索和分类管理。

#### 2.3.2 标签分类

| 标签维度 | 自动生成示例 | 说明 |
|---------|-------------|------|
| 合同类型 | 采购合同、销售合同、NDA | 基于内容分类 |
| 风险等级 | 🔴高 / 🟡中 / 🟢低 | 基于条款分析 |
| 业务领域 | IT/制造/金融/医药 | 行业识别 |
| 关键条款 | 有保密条款、有竞业限制、有自动续签 | 条款检测 |
| 金额区间 | <10万 / 10-100万 / >100万 | 金额范围 |
| 关联方 | 与XX公司相关 | 主体识别 |
| 时效性 | 即将到期(30天内) / 已逾期 | 动态标签 |
| 合规标签 | 需数据合规审查 / 需反垄断审查 | 合规标记 |

#### 2.3.3 标签管理
1. **自动标签**：AI自动分析生成，支持设置标签生成规则
2. **自定义标签**：用户可手动添加标签，支持标签层级（父子标签）
3. **标签推荐**：基于已有合同库，推荐最相关的10个标签
4. **批量打标签**：选中多份合同，批量添加/移除标签
5. **标签统计**：标签云展示，点击标签查看关联合同数量

#### 2.3.4 AI标签生成机制
```
合同文本 → 文本分段 → 特征提取
    ↓                      ↓
  标签输出 ←── 多标签分类模型 ←── 上下文理解
    ↓
  后处理(去重/排序/置信度过滤)
    ↓
  最终标签集(附带置信度分数)
```

### 功能四：合同精确检索 (Precise Contract Search)

#### 2.4.1 功能描述
支持全文检索、语义检索、结构化检索的多模态搜索能力。

#### 2.4.2 检索类型

| 检索方式 | 示例 | 技术实现 |
|---------|------|---------|
| 关键词检索 | 输入"保密条款 违约金" | Elasticsearch全文索引 |
| 语义检索 | 输入"哪些合同涉及保密义务" | 向量嵌入+语义匹配 |
| 字段检索 | "金额>100万 AND 状态=履行中" | 结构化查询 |
| 混合检索 | 关键词+语义+字段组合 | 多路召回+融合排序 |
| 正则检索 | "合同编号:CT-\d{8}" | 正则表达式查询 |

#### 2.4.3 高级检索功能
1. **自然语言检索**：直接用自然语言描述要找的合同
   - 示例："去年签订且金额超过50万的采购合同"
   - 示例："包含自动续签条款的租赁合同"
2. **语义相关度排序**：搜索结果按语义相关度排序，而非纯关键词匹配
3. **搜索结果高亮**：在文档预览中高亮匹配位置
4. **搜索建议**：输入时自动补全、拼写纠错、相关搜索推荐
5. **检索历史**：保存历史搜索记录，支持快速重新搜索
6. **保存搜索条件**：将常用搜索条件保存为预设

### 功能五：AI合同内容基础问答 (AI-Powered Contract Q&A)

#### 2.5.1 功能描述
基于RAG（检索增强生成）技术，用户可对单份或多份合同内容进行自然语言问答，AI精准定位合同条款给出答案。

#### 2.5.2 典型问答场景

| 问题类型 | 示例 |
|---------|------|
| 条款查询 | "这份合同的违约金是多少？" |
| 条件询问 | "提前解约需要提前多久通知？" |
| 对比分析 | "这两份合同的付款方式有什么不同？" |
| 责任界定 | "如果延迟交货，乙方需要承担什么责任？" |
| 日期询问 | "这份合同什么时候到期？还有续签选项吗？" |

#### 2.5.3 问答交互设计
1. **合同问答面板**：在合同详情页右侧嵌入问答面板
2. **引用高亮**：AI回答时引用具体条款，点击引用跳转到原文位置
3. **追问能力**：支持基于上下文的多轮对话
4. **预设问题**：AI自动推荐"您可能想问的"问题列表
5. **答案可信度**：标注答案的置信度和引用来源

#### 2.5.4 问答界面设计
```
┌─────────────────┬────────────────────────┐
│  合同预览区域    │  💬 AI问答助手          │
│                 │                        │
│  合同内容展示    │  建议问题:             │
│  ...            │  ▶ 违约金是多少？       │
│  第12条 违约责任 │  ▶ 合同何时到期？      │
│  ...            │  ▶ 付款条件是什么？     │
│                 │                        │
│                 │  ──────────────────    │
│                 │                         │
│                 │  用户: 这份合同能否自动  │
│                 │  续签？续签条件是什么？  │
│                 │                         │
│                 │  AI: 根据合同第8.2条...  │
│                 │  [引用: 第8.2条]        │
│                 │  [置信度: 高]           │
│                 │                         │
│                 │  ┌──────────────────┐   │
│                 │  │ 输入问题... [发送] │   │
│                 │  └──────────────────┘   │
```

#### 2.5.5 技术架构
```
用户问题 → 问题理解/改写
    ↓
  向量检索(语义相似度) + 关键词检索(BM25)
    ↓
  多路召回 → 重排序(Reranker)
    ↓
  LLM生成答案 + 引用标记
    ↓
  输出: 答案 + 引用条款 + 置信度
```

### 功能六：提炼合同摘要 (Contract Summary Extraction)

#### 2.6.1 功能描述
AI自动从合同全文中提炼核心摘要，支持多粒度、多角度的摘要生成。

#### 2.6.2 摘要类型

| 摘要类型 | 长度 | 内容侧重 |
|---------|------|---------|
| 一句话摘要 | 1句话 | 合同最核心内容 |
| 简短摘要 | 3-5条 | 核心要素列表 |
| 详细摘要 | 一段话 | 全面概述 |
| 分角色摘要 | 不定 | 分别从甲方/乙方视角总结权责 |
| 风险摘要 | 1段 | 仅提炼风险相关条款 |
| 时间线摘要 | 列表 | 按时间顺序排列关键日期节点 |

#### 2.6.3 摘要内容结构
```json
{
  "one_line": "XX公司与YY公司就Z项目签订总金额为XXX万元的采购合同，合同期限为2024.1.1-2025.12.31",
  "key_points": [
    "合同金额: 500万元 (含税)",
    "合同期限: 2年 (2024.1.1-2025.12.31)",
    "付款方式: 合同签订付30%，验收合格付60%，质保期满付10%",
    "违约责任: 逾期交货每日按合同总额0.5‰支付违约金",
    "争议解决: 提交XX仲裁委员会仲裁"
  ],
  "risk_highlights": [
    "⚠️ 违约金比例较高(每日0.5‰，年化18.25%)",
    "⚠️ 无不可抗力条款",
    "⚠️ 自动续签条款对甲方不利"
  ],
  "timeline": [
    "2024.1.1 合同生效",
    "2024.3.31 第一批交货截止",
    "2024.6.30 项目验收截止",
    "2025.12.31 质保期届满"
  ]
}
```

#### 2.6.4 摘要展示设计
- **摘要卡片**：在合同列表页以卡片形式展示
- **摘要标签页**：在合同详情页作为独立标签页
- **一键复制**：支持复制摘要到剪贴板
- **导出摘要**：导出为PDF/Word格式
- **人工修订**：用户可编辑AI生成的摘要，修订记录保存

### 功能七：合同版本对比 (Contract Version Comparison)

#### 2.7.1 功能描述
支持同一合同不同版本间的差异对比，AI自动识别变更内容并进行语义分析。

#### 2.7.2 版本管理
1. **版本历史**：每次编辑/上传自动生成新版本
2. **版本标注**：支持对版本打标签（如"法务审核版""对方修订版""终版"）
3. **版本回滚**：一键回滚到历史版本
4. **版本分支**：支持多分支版本（如：我方修订分支 vs 对方修订分支）

#### 2.7.3 对比功能

| 对比维度 | 展示方式 | 说明 |
|---------|---------|------|
| 文本差异 | 并排/逐行对比 | 增删改标记(红/绿/黄) |
| 条款级对比 | 条款对应展示 | 逐条款对比变更 |
| 金额变化 | 高亮标注 | 数字变化自动标红 |
| 结构变化 | 大纲对比 | 章节结构增减识别 |

#### 2.7.4 AI智能对比增强
1. **语义变更识别**：不仅是文本差异，AI识别条款意思变化
   - 示例："甲方应承担" → "乙方应承担" → AI标注"责任主体变更"
2. **风险变更预警**：对比结果中标记新增/修改的风险条款
3. **变更摘要**：AI自动生成版本变更摘要
   - "本次修订共修改3处：① 付款比例由30%调整为20%；② 新增保密条款；③ 删除第9条自动续签"
4. **合规检查**：对比修订内容是否符合法规要求

#### 2.7.5 对比界面设计
```
┌─────────版本历史─────────┐
│  v1.0 (原始版)  ← 对比    │
│  v1.1 (法务审核)  → 对比  │
│  v2.0 (对方修订)          │
│  v2.1 (终版) *当前        │
└──────────────────────────┘

┌───── v1.0 (原始版) ─────┬──── v1.1 (法务审核) ────┐
│                         │                         │
│  第5条 付款方式         │  第5条 付款方式          │
│                         │                         │
│  甲方应在合同签订后    │  甲方应在收到乙方发票后    │
│  █30日█内支付30%      │  █15个工作日█内支付30%   │
│  预付款...              │  预付款...               │
│                         │                         │
│  变更: 付款触发条件     │  ← AI标注               │
│  变更: 付款期限         │  ← AI标注               │
└─────────────────────────┴─────────────────────────┘

AI变更摘要:
✅ 共检测到5处变更
🔴 风险变更: 付款条件变更(对甲方更有利)
📝 新增条款: 第12条 保密义务(新增)
🗑️ 删除条款: 第9条 自动续签(已删除)
```

## 三、AI架构设计

### 3.1 AI能力矩阵

| AI能力 | 使用场景 | 技术方案 |
|--------|---------|---------|
| OCR识别 | 合同导入 | 多模态大模型 / PaddleOCR |
| 信息抽取 | 合同解析 | LLM + NER + 结构化提取 |
| 文本分类 | 智能标签 | 多标签分类模型 |
| 语义搜索 | 合同检索 | Embedding + 向量库(Milvus/Qdrant) |
| RAG问答 | 合同问答 | LLM + 向量检索 + 重排序 |
| 文本摘要 | 摘要提炼 | LLM + 分块摘要策略 |
| 文本对比 | 版本对比 | Diff算法 + LLM语义分析 |
| 实体识别 | 主体/金额提取 | NER模型 |

### 3.2 数据处理管道
```
文档入库
  ↓
文档解析层 (OCR / PDF解析 / Doc解析)
  ↓
文本分块 (Chunking Strategy: 滑动窗口/语义分块)
  ↓
向量化 (Embedding: text-embedding-3/large)
  ↓
元数据提取 (NER / 分类 / 摘要)
  ↓
数据存储 (向量库 + 全文索引 + 关系数据库)
  ↓
索引构建 (ES索引 / 向量索引)
```

### 3.3 RAG问答架构
```
用户问题
  ↓
Query理解 (改写/分解/意图识别)
  ↓
 ┌─────────────────────────────┐
 │ 多路检索                    │
 │  ├─ 向量检索 (语义匹配)      │
 │  ├─ BM25关键词检索           │
 │  └─ 结构化字段检索           │
 └─────────────┬───────────────┘
               ↓
 重排序 (Cross-Encoder Reranker)
               ↓
 上下文拼装 (Prompt Engineering)
               ↓
 LLM生成 (GPT-4 / Claude / 千问)
               ↓
 后处理 (引用标记/格式美化/置信度)
               ↓
        返回给用户
```

## 四、用户旅程

### 4.1 核心用户旅程图

## 八、AI原生设计原则总结

1. **AI First**：所有功能默认由AI驱动，人工仅做确认和补位
2. **逐步信任**：AI输出附带置信度和引用来源，帮助用户建立信任
3. **人机协同**：AI不替代人，而是做"初稿"和"辅助"，让人做"决策"
4. **持续学习**：用户反馈作为训练数据，模型持续优化
5. **上下文感知**：AI理解用户当前在做什么，提供主动式帮助
6. **多模态融合**：文本、表格、图片多种信息形式融合处理
